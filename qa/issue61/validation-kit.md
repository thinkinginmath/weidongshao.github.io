# Outside-user task validation

Owner recruits 10–20 people who have scattered Mac/drive photos. No outreach was sent by this implementation. No results or testimonials have been invented.

Use build 80, a small backed-up sample folder and a second connected source. Ask permission before observing a personal library; record task outcomes, not filenames or screenshots, unless separately agreed.

## Five tasks, without coaching

1. After 15 seconds on the homepage, explain what MyMedia does, where files live and whether a new library/account is required.
2. Download the right Mac build and add the sample folder. Ask where the originals are now.
3. Find one older photo by a date in its filename. Note the first attempted query and whether the result is found.
4. Review an exact-copy group spanning folders; identify the keeper and what Move to Trash will affect. Stop before removal unless the participant has explicitly approved disposable copies.
5. Preview organization into an empty destination. Explain the chosen scope, Copy versus Move, free space and undo. Do not apply to an unbacked-up library.

For people gathering devices, ask them to find the optional gather/preserve/tidy path and explain how it differs from indexing in place. For an iPhone user, ask which Apple tool imports and which MyMedia operation verifies the copied folder; no phone deletion is required.

## Record consistently

Participant code; Mac/OS; source type; prior photo-tool experience; task success without help / with help / failed; time to outcome; wrong turns; exact confusing UI words; confidence 1–5; whether they would use it on their own photos and why. Keep identifying details out of the aggregate report.

After each group of five, fix recurring confusion and rerun the affected tasks with fresh participants. Compare homepage comprehension, successful add/search/duplicate/preview completion and confidence; report the sample size, build and assistance given. Do not turn this convenience sample into market-wide performance claims.

## Measurement baseline and comparison

The baseline.json records the pre-publication rolling Cloudflare view. Host request totals include assets/bots/errors, not visitors. The dashboard did not expose product-specific download/conversion totals, so those are unknown.

After publication, record the same UTC date windows, host filter and status/path definitions. Separate HTML requests, download-page requests, R2 DMG requests/bytes, appcast requests and confirmed provider subscriptions. A DMG request can be partial/retried; update checks are not unique DAU. Do not claim conversion rates across differently scoped counters. No GA, session replay, tracking pixels or browser IDs are added.
